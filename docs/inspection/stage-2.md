# 阶段 2 验收清单：可选插件

> 阶段目标：实现重型可选插件（MathJax、语法高亮、附件、补全、i18n），确保 tree-shakeable——不引入则零开销。
> 本阶段不涉及新架构概念，纯粹是独立插件的实现和验证。

---

## 一、插件就位清单

| # | 插件 ID | 说明 |
|---|---------|------|
| 2.1 | `math` | MathJax 数学公式渲染。不 import 此插件则不加载 MathJax |
| 2.2 | `syntax-highlight` | 代码块按语言懒加载高亮 mode。不 import 则不加载 modes.min.js |
| 2.3 | `attachment` | 粘贴图片/拖拽文件 → 先插入占位 → 异步上传 → 替换为最终 URL |
| 2.4 | `suggest` | 通用自动补全框架。输入 `[[` 弹出笔记列表（需 `listLinkTargets`） |
| 2.5 | `i18n` | DI 注入翻译函数，中文优先 |

## 二、验收步骤

### 步骤 1：MathJax 插件（math）

准备包含数学公式的测试文档：

```markdown
## 数学公式

行内公式：$E = mc^2$

块级公式：
$$
\sum_{n=1}^{\infty} \frac{1}{n^2} = \frac{\pi^2}{6}
$$
```

| 测试场景 | 操作 | 期望行为 |
|---------|------|---------|
| 不加载 math 插件 | 打开含公式的文档 | 公式显示为原始 LaTeX 源码（`$E = mc^2$`） |
| 加载 math 插件 | `editor.use(mathPlugin)` | 公式渲染为排版后的数学符号 |
| 行内公式 | 光标进入含 `$...$` 的行 | 显示原始 LaTeX，光标离开后恢复渲染 |
| 块级公式 | 光标进入 `$$...$$` 区域 | 显示原始 LaTeX，光标离开后恢复渲染 |

**验收标准**：公式渲染正确（与 Obsidian 桌面端对比）。bundle 不引入 MathJax 时构建产物体积无明显增加。

### 步骤 2：语法高亮插件（syntax-highlight）

准备包含多语言代码块的测试文档（JavaScript、Python、CSS、Bash、JSON）。

| 测试场景 | 操作 | 期望行为 |
|---------|------|---------|
| 不加载 syntax-highlight 插件 | 打开含代码块的文档 | 代码块无语法高亮（单色文本） |
| 加载 syntax-highlight 插件 | `editor.use(syntaxHighlightPlugin)` | 代码块按语言正确高亮 |
| JavaScript | ` ```javascript ` | 关键字、字符串、注释分别着色 |
| Python | ` ```python ` | 关键字、字符串、注释分别着色 |
| CSS | ` ```css ` | 属性、值、选择器分别着色 |
| 未知语言 | ` ```someunknownlang ` | 回退为无高亮（不报错、不崩溃） |

**验收标准**：常见语言（JS/Python/CSS/Bash/JSON）高亮正确。未知语言不报错。

### 步骤 3：附件插件（attachment）

| 测试场景 | 操作 | 期望行为 |
|---------|------|---------|
| 粘贴图片 | 从剪贴板粘贴截图 | 编辑器内立即出现图片占位，然后替换为最终图片（`saveAttachment` 返回的 URL） |
| 拖拽图片 | 从文件管理器拖拽图片到编辑器 | 同上 |
| 拖拽非图片文件 | 拖拽 .md 或 .pdf 文件 | 插入 `[[filename]]` 链接 |
| 后端未提供 saveAttachment | 粘贴图片 | 静默失败（不报错），不插入任何内容 |

**验收标准**：图片粘贴/拖拽流程完整（先插入后上传）。`saveAttachment` 接口被正确调用。

### 步骤 4：自动补全插件（suggest）

| 测试场景 | 操作 | 期望行为 |
|---------|------|---------|
| 无 listLinkTargets | 输入 `[[` | 不弹出补全框 |
| 有 listLinkTargets | 输入 `[[` 后继续输入文字 | 弹出匹配的笔记列表，可按上下键选择、Enter 确认、Esc 取消 |
| 补全确认 | 选中候选按 Enter | 插入 `[[target]]`，光标在 `]]` 之后 |
| 别名支持 | 后端返回 aliases | 候选项显示别名信息 |
| 自定义 suggest | 通过 `registerSuggest()` 注册自定义触发 | 自定义补全能正常弹出和选择 |

**验收标准**：补全弹窗正确、键盘导航正常、不会残留在 DOM 中。

### 步骤 5：i18n 插件（i18n）

| 测试场景 | 操作 | 期望行为 |
|---------|------|---------|
| 不提供 I18nProvider | 默认行为 | 使用内置英文文案（如有 UI 文案） |
| 提供中文 I18nProvider | 注入翻译函数 | UI 显示中文 |

**验收标准**：i18n 接口工作正常，不影响编辑器核心功能。

## 三、关注点

| 关注 | 不关注 |
|------|--------|
| 不 import 的插件是否真的不被打包（tree-shake 验证） | 所有语言的高亮 mode 是否完整（后续按需添加） |
| MathJax 字体在 `file://` 协议下是否正常（通过 AssetLoader DI 解决） | i18n 翻译覆盖率（只需 demo 级别） |
| 图片粘贴的"先插入后上传"体验是否流畅 | 图片上传进度条 |
| 补全弹窗的键盘操作完整性 | 补全排序算法 |
| 插件间互不干扰 | 插件的性能优化 |

## 五、人类检查要点

1. **Tree-shake 验证**：分两次构建——一次不 import 可选插件，一次全部 import。对比 `dist/` 体积差异，确认不引入 MathJax 时体积无显著增加。
2. **MathJax 渲染质量**：对照 Obsidian 桌面端的公式渲染效果，检查字体、间距、对齐。
3. **语法高亮正确性**：对照 VS Code 或 GitHub 的同语言高亮，检查颜色分配是否合理。
4. **补全弹窗不残留**：多次打开关闭补全弹窗、切换编辑器焦点，确认弹窗 DOM 不会残留。
