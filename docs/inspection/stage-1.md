# 阶段 1 验收清单：内核 + 基础插件

> 阶段目标：复刻 Obsidian 最小可用体验——在 `apps/web` 中打开 Markdown 文档，获得与 Obsidian 一致的即时渲染（Live Preview）。
> 本阶段是整个项目最关键的里程碑。通过后，xlxz-markdown-editor 具备 alpha 级可用性。

---

## 一、插件就位清单

阶段 1 应实现以下 16 个基础插件。人类逐项在 `apps/web` 中验证。

| # | 插件 ID | 验证方式 |
|---|---------|---------|
| 1.1 | `live-preview` | 光标离开某行后，markdown 语法符号隐藏，显示渲染效果。光标进入该行，语法符号重现 |
| 1.2 | `markdown-language` | 代码块有语法高亮、不同语法节点有对应的 CSS class |
| 1.3 | `theme` | 编辑器有完整的 Obsidian 风格样式（暗色/亮色），CSS 变量可通过 `cssVariables` 选项覆写 |
| 1.4 | `hanging-indent` | 列表项换行后，文字对齐到项目符号之后 |
| 1.5 | `list-continuation` | 列表项末尾按 Enter 自动插入下一个列表标记；空列表项按 Enter 删除标记 |
| 1.6 | `markdown-surround` | 选中文字后输入 `*` 用 `*文字*` 包围而非替换 |
| 1.7 | `close-brackets` | 输入 `(` 自动补 `)`；输入 `**` 自动补 `**`；在代码块内不配对 |
| 1.8 | `frontmatter` | `---` 包裹的 YAML 区域有语法高亮，可折叠 |
| 1.9 | `wiki-link` | `[[target]]` 渲染为链接样式，`[[target\|alias]]` 显示别名；已解析/未解析链接颜色不同 |
| 1.10 | `callout` | `> [!NOTE]` 等渲染为带背景色和图标的提示块 |
| 1.11 | `tag-render` | `#tag` 渲染为可点击的标签 pill |
| 1.12 | `expand-text` | 输入 `【【` 自动变为 `[[`，输入 `】】` 自动变为 `]]` |
| 1.13 | `embed` | `![[image.png]]` 显示图片（需要提供 `getResourceUrl`） |
| 1.14 | `fold` | 标题左侧有折叠箭头，点击可折叠/展开该标题下的内容 |
| 1.15 | `line-numbers` | 编辑器左侧显示行号，当前行行号高亮 |
| 1.16 | `indent-guide` | 列表和 blockquote 缩进处显示垂直指引线 |

## 二、验收步骤

### 步骤 1：加载 demo 文档

`apps/web` 应加载一份覆盖所有 Markdown 语法的 demo 文档（可从 md-live-preview 的 `demo-doc.md` 迁移）。

**验收标准**：文档在编辑器中正常显示，有行号、有内容。

### 步骤 2：Live Preview 核心体验

逐个验证以下交互（这是验收核心，花最多时间）：

| 测试场景 | 操作 | 期望行为 | 验收结果 |
|---------|------|---------|---|
| 标题渲染 | 光标在 `# 标题` 行外 | `#` 符号隐藏，文字以标题样式（大号、粗体）显示 | 正确 |
| 标题编辑 | 光标点击 `# 标题` 行 | `#` 符号显示，文字恢复正常大小 | 正确 |
| 粗体渲染 | 光标离开 `**bold**` | `**` 隐藏，文字粗体 | 正确 |
| 粗体编辑 | 光标点击 `**bold**` | `**` 显示 | 正确 |
| 斜体渲染 | 光标离开 `*italic*` | `*` 隐藏，文字斜体 | 正确 |
| 链接渲染 | 光标离开 `[text](url)` | 方括号和圆括号隐藏，显示为蓝色下划线链接 | 正确 |
| 链接编辑 | 光标点击链接 | 完整 markdown 语法显示 | 正确 |
| Wiki-link 渲染 | 光标离开 `[[target]]` | 显示为链接样式 | 正确 |
| 图片渲染 | 光标离开 `![alt](url)` | 显示为图片 | 正确 |
| 代码块渲染 | 光标离开 ` ``` ` 区域 | 代码块有背景色，语法高亮 | 背景色可能和默认背景一致，无法分辨 |
| Blockquote | 光标离开 `> text` | `>` 隐藏，文字有左边框和背景色 | 正确 |
| 无序列表 | 光标离开 `- item` | `- ` 隐藏，显示为 bullet | 正确 |
| 有序列表 | 光标离开 `1. item` | `1. ` 隐藏，显示为序号 | 正确 |
| 任务列表 | 光标离开 `- [ ] task` | 显示为可勾选的复选框 | 正确 |
| Callout | 光标离开 `> [!NOTE]` | 显示为带图标的提示块 | 正确 |
| 标签 | 光标离开 `#tag` | 显示为标签 pill | 默认给的两个示例渲染正确，后续我自己写入的没有被渲染 |
| 删除线 | 光标离开 `~~text~~` | `~~` 隐藏，文字有删除线 | 正确 |
| 高亮 | 光标离开 `==text==` | `==` 隐藏，文字有高亮背景 |高亮样式没看到，但是行为正确|
| 水平线 | 光标离开 `---` | 显示为水平分割线 | 正确 |

**验收标准**：上表所有测试场景通过。任意一个不一致 → 不通过。

### 步骤 4：自动配对

| 测试场景 | 操作 | 期望行为 |验收结果 |

### 步骤 5：中文输入体验

| 测试场景 | 操作 | 期望行为 |验收结果 |
|---------|------|---------|---|
| 全角转换 | 输入 `【【` | 自动变为 `[[` | 正确 |
| 全角转换 | 输入 `】】` | 自动变为 `]]` | 正确 |
| 带感叹号 | 输入 `！【【` | 自动变为 `![[` | 正确 |

> 建议增加 ··· -> ```
> 因为类似 【和[ ,中文输入下，` 号键 被输入为 · 且，三个连续的 ··· 在正常中文输入中极少。

**验收标准**：上表所有测试场景通过。

### 步骤 6：CSS 变量覆写

通过 `cssVariables` 选项传入自定义变量：

```typescript
createEditor(container, {
  cssVariables: {
    '--font-text': '"Noto Serif SC", serif',
    '--font-text-size': '18px',
  }
})
```

**验收标准**：字体和字号变化可见。

### 步骤 7：回调验证

| 回调 | 操作 | 期望行为 |

**验收标准**：回调正常触发，参数正确。

## 三、关注点

| 关注 | 不关注 |
|------|--------|
| Live Preview 渲染是否与 Obsidian 行为一致 | 可选插件（MathJax、语法高亮的语言完整性） |
| 光标进入/离开行时符号显示/隐藏切换是否即时 | 性能优化（大文档 10000+ 行） |
| 列表续行、自动配对、中文转换等功能是否正确 | npm 发布流程（alpha 版本地验证即可） |
| CSS 变量覆写是否生效 | 在线 playground / 文档 |
| `onChange` 回调是否正确触发 | iNote 集成适配 |
| 所有基础插件是否可以通过 `editor.use()` 注册和卸载 | 包体积优化 |

## 五、人类检查要点

1. **Live Preview 是核心**：花 80% 的验收时间在步骤 2。对照 Obsidian 桌面端的实际行为，逐项对比。
2. **边界情况**：尝试在列表内嵌 code block、在 blockquote 内嵌列表等嵌套场景。当前阶段允许少量不一致（记录为 known issues），但不能有崩溃或渲染错误。
3. **不应该出现的行为**：编辑器崩溃、DOM 异常、控制台红色错误、数据丢失（输入的文本消失）。
4. **对比基准**：在 Obsidian 桌面端打开同样的 demo 文档，切换 live preview 模式，作为验收的参照物。
