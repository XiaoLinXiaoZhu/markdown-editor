# 阶段 4 验收清单：iNote 集成验证

> 阶段目标：在真实的 Tauri 桌面应用中替换 vditor，验证 xlxz-markdown-editor 在非浏览器环境下的表现。
> 本阶段是项目的"实战检验"——发现阶段 1-3 中未曾暴露的集成问题。

---

## 一、集成改动范围

| # | 改动 | 文件（iNote 侧） | 说明 |
|---|------|-----------------|------|
| 4.1 | 替换编辑器组件 | `src/views/editor/components/IEditor.vue` | 用 xlxz-markdown-editor 替代 vditor |
| 4.2 | 适配图片存储 | `IEditor.vue` 中 `insertImage` | vditor 的 `upload.handler` → `EditorBackend.saveAttachment` |
| 4.3 | 适配链接导航 | 新建 `backend.openFile` 实现 | 使用 Tauri `@tauri-apps/plugin-shell` 打开外部链接 |
| 4.4 | 适配便签列表预览 | `src/views/index/components/List.vue` | vditor 的 `getHTML()` → 用第三方 markdown parser 生成 HTML 预览 |
| 4.5 | 适配右键菜单 | `IEditor.vue` 中 `contextMenu` | 从 vditor API（`getSelection()`）迁移 |
| 4.6 | 移除 vditor 依赖 | `package.json` | 删除 `vditor` 和 `vditor/dist/index.css` |

## 二、验收步骤

### 步骤 1：基础编辑功能

在 iNote 中创建新便签，进行以下操作：

| 测试场景 | 操作 | 期望 |
|---------|------|------|
| 输入文字 | 输入 Markdown 文本 | Live Preview 渲染正常（与 Obsidian 一致） |
| 中文输入 | 使用中文输入法输入 | 无输入法兼容问题 |
| 粗体/斜体 | 使用 `**bold**` 和 `*italic*` | 渲染正常 |
| 列表 | 创建无序/有序/任务列表 | 列表续行、Tab 缩进正常 |
| 标题 | 使用 `#` 创建标题 | 标题渲染和折叠正常 |
| 代码块 | 创建 ` ```js ` 代码块 | 语法高亮正常 |
| 链接 | 点击 `[text](url)` | 系统浏览器打开链接 |
| Wiki-link | 点击 `[[target]]` | 行为由 `onLinkClick` 控制（当前可无操作或导航到对应便签） |

**验收标准**：基础编辑体验与阶段 1 的 `apps/web` 一致。

### 步骤 2：图片处理

| 测试场景 | 操作 | 期望 |
|---------|------|------|
| 粘贴截图 | 在便签中粘贴剪贴板截图 | 图片立即显示占位，异步上传后替换为 `atom:///path` |
| 拖拽图片 | 从文件管理器拖拽图片到便签 | 同上 |
| 图片显示 | 已有图片的便签重新打开 | 图片正确加载（通过 `getResourceUrl` → `atom:///` 协议） |
| 图片文件夹 | 便签对应的图片文件夹正确创建 | `{appDataDir}/images/{uid}/` 存在 |

**验收标准**：图片粘贴/拖拽/显示流程完整，无 broken image。

### 步骤 3：便签列表预览

在便签列表页：

| 测试场景 | 期望 |
|---------|------|
| 列表卡片显示 | 每个便签卡片显示前几行内容的 HTML 预览 |
| 新建便签 | 列表中实时出现新便签卡片 |
| 编辑便签后返回列表 | 卡片预览更新为最新内容 |
| 删除便签 | 卡片从列表中移除 |

**验收标准**：列表预览与之前 vditor 版本功能对等。

### 步骤 4：多窗口

| 测试场景 | 操作 | 期望 |
|---------|------|------|
| 打开多个便签 | 从列表打开 3 个不同的便签 | 每个便签在独立窗口中正常工作 |
| 窗口间独立 | 在一个窗口中编辑 | 不影响其他窗口的编辑器状态 |
| 关闭窗口 | 关闭一个便签窗口 | 其他窗口不受影响，列表更新 |

**验收标准**：多窗口场景无状态污染、无崩溃。

### 步骤 5：沉浸模式

| 测试场景 | 操作 | 期望 |
|---------|------|------|
| 失去焦点隐藏 UI | 点击便签窗口外 | 编辑器 UI 元素隐藏（和当前 iNote 行为一致） |
| 获得焦点显示 UI | 点击便签窗口内 | UI 恢复显示 |
| ESC 最小化 | 在便签窗口中按 Esc | 窗口最小化 |

**验收标准**：沉浸模式行为与之前一致。

### 步骤 6：持久化

| 测试场景 | 操作 | 期望 |
|---------|------|------|
| 编辑后关闭 | 输入文字后关闭窗口 | 内容正确保存到数据库 |
| 重新打开 | 重新打开该便签 | 内容完整恢复（markdown 原文） |
| 空便签 | 打开空便签后直接关闭 | 空便签被正确清理（不残留） |

**验收标准**：数据持久化正确，不丢数据、不留垃圾。

## 三、关注点

| 关注 | 不关注 |
|------|--------|
| 在 Tauri webview 中的兼容性（file:// 协议、自定义协议） | 便签列表的性能优化 |

| 多窗口内存泄漏 | 新功能开发 |
| 数据持久化正确性 | UI 美化 |
| 与现有 Tauri API 的集成稳定性 | 迁移期间 iNote 原有功能的回归（允许在独立分支上进行） |

## 五、人类检查要点

1. **在 iNote 的独立分支上进行**：不要直接修改 main 分支。阶段 4 的改动在独立分支完成，验收通过后再合并。
2. **对比旧版**：验收时同时打开旧版（vditor）和新版（xlxz）两个 iNote 实例，对比编辑体验的差异。
3. **边界条件**：极端长的便签（10000+ 行）、大量图片的便签、包含特殊字符的便签。
4. **Tauri 构建**：执行 `bun run tauri:build` 确认生产构建无问题。
5. **降级方案**：如果阶段 4 验收不通过，保留回退到 vditor 的能力（独立分支不删除，直到确认稳定）。
